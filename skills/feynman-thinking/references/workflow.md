# 상세 작업 흐름

이 문서는 L2~L3 작업 또는 사용자가 전체 검증 과정을 요구할 때만 읽는다. 절차를 의례적으로 모두 채우지 말고, 결론을 바꿀 수 있는 단계에 자원을 집중한다.

## 1. 문제 계약

### 1.1 실제 문제를 찾는다

사용자의 문장을 그대로 해결 대상으로 고정하지 않는다. 다음 세 문장을 작성한다.

1. 사용자가 표면적으로 요구한 것
2. 실제로 결정하거나 만들어야 하는 것
3. 잘못 답했을 때 발생하는 손실

### 1.2 성공 기준을 관찰 가능하게 만든다

`좋다`, `견고하다`, `효율적이다`와 같은 표현은 판정 기준이 아니다. 가능한 경우 수치, 통과 조건, 사용자의 행동, 재현 가능한 테스트로 바꾼다.

### 1.3 모호성을 처리한다

- 결과를 크게 바꾸는 모호성만 확인한다.
- 나머지는 합리적 가정을 세우고 `[ASSUME]`로 표시한다.
- 가정별로 결론이 달라지면 분기 시나리오를 작성한다.

## 2. 현상 지도

다음 요소를 한 장의 표 또는 간단한 모델로 정리한다.

| 요소 | 질문 |
|---|---|
| 대상 | 실제로 관찰·조작·결정하는 것은 무엇인가? |
| 상태 | 어떤 속성이 시간 또는 조건에 따라 달라지는가? |
| 입력 | 무엇이 계에 들어오는가? |
| 출력 | 무엇을 측정하거나 얻는가? |
| 관계 | 무엇이 무엇에 어떤 방향으로 영향을 주는가? |
| 환경 | 모델 밖 조건이 결과에 어떤 흔적을 남기는가? |
| 제약 | 물리·논리·법·비용·시간 중 바꿀 수 없는 것은 무엇인가? |
| 미지 | 현재 확인하지 못한 핵심은 무엇인가? |

## 3. 표현 탐색

최소 두 표현을 짧게 비교한다. 다음 중 필요한 것만 쓴다.

- 작동 과정의 자연어 설명
- 변수와 관계식
- 인과 그래프
- 상태 전이표
- 공간·시간 도식
- 최소 반례
- 장난감 모델
- 시뮬레이션 또는 프로토타입

표현 선택 기준:

1. 숨은 가정을 드러내는가?
2. 관련 없는 자유도를 줄이는가?
3. 귀결을 쉽게 도출하는가?
4. 독립 검증이 가능한가?
5. 현실과의 연결 고리를 보존하는가?

표현이 달라졌는데 결론이 달라지면 동치성 가정이 깨진 것이다. 어느 표현이 무엇을 생략했는지 추적한다.

## 4. 모델 구성

### 4.1 최소 모델

최소 모델은 결론에 필요한 가장 적은 변수와 관계만 포함한다. 단, 단순하다는 이유만으로 채택하지 않는다. 관찰량을 설명하고 판별 가능한 결과를 내야 한다.

### 4.2 대안 모델

최소한 다음 중 하나를 둔다.

- 기존 통념 또는 기준선
- 반대 인과 방향
- 누락 변수 설명
- 더 단순한 무효 모델
- 더 현실적인 복합 모델

### 4.3 환경 효과 보존

변수를 제거할 때 다음 중 하나로 효과를 남긴다.

- 경계 조건
- 유효 계수 또는 항
- 제약 조건
- 오차·교란 항
- 외부 영향 시나리오
- 적용 범위의 축소

## 5. 근사 원장

근사를 사용하면 반드시 다음 질문에 답한다.

1. 정확한 출발점은 무엇인가?
2. 어느 단계에서 근사가 들어갔는가?
3. 무엇을 작다고, 느리다고, 독립적이라고, 선형이라고 가정했는가?
4. 버린 항이나 정보는 무엇인가?
5. 유효한 매개변수 범위는 어디인가?
6. 오차를 계산·상한·경험 비교 중 어떤 방식으로 평가했는가?
7. 근사가 실패할 때 어떤 신호가 나타나는가?
8. 더 정밀한 보정 방법은 무엇인가?

## 6. 귀결과 판별 검사

각 모델에 대해 다음 형식으로 쓴다.

```text
모델이 맞다면:
관찰/계산되어야 하는 것:
경쟁 모델과 달라지는 지점:
모델을 약화시키는 결과:
모델을 폐기하거나 범위를 줄일 결과:
```

모든 성공 사례가 판별력 있는 것은 아니다. 경쟁 모델도 같은 결과를 설명하면 증거의 힘을 낮춘다.

## 7. 검증 계획

검사를 다음 순서로 우선순위화한다.

1. 싸고 치명적인 검사: 정의 모순, 단위, 부호, 간단한 반례
2. 핵심 가정을 직접 공격하는 검사
3. 경쟁 모델을 구별하는 검사
4. 정량 오차·민감도·자원 검사
5. 비싼 실험·프로토타입·독립 검토

각 검사의 결과는 `통과`, `실패`, `미검증`, `판별력 부족` 중 하나로 기록한다.

## 8. 수정 루프

검증 실패를 다음 층으로 분류한다.

- 자료 실패
- 계산 실패
- 정의 실패
- 가정 실패
- 표현 실패
- 모델 실패
- 적용 범위 실패
- 구현·자원 실패

실패가 발견되면 결론을 방어하지 말고 해당 층을 수정한다. 수정 전후의 차이와 결론 변화량을 남긴다.

## 9. 종료 규칙

다음 중 하나일 때 현재 작업을 종료한다.

- 성공 기준을 충족하고 중요한 반대 증거를 처리했다.
- 추가 검증의 기대 가치가 비용보다 작다.
- 핵심 정보가 없어 조건부 결론 이상으로 나아갈 수 없다.
- 모델들이 현재 자료에서 구별되지 않아 다음 판별 검사가 명확해졌다.

종료는 완전한 지식의 선언이 아니다. 남은 공백을 보존한 채 현재 결정에 충분한 상태를 뜻한다.
