# feynman-thinking

복잡한 문제를 그럴듯한 설명에서 **직접 검토 가능한 현상·모델·계산·검사·수정 기록**으로 바꾸는 Agent Skill입니다.

이 스킬은 리처드 파인만의 말투나 성격을 흉내 내지 않습니다. 파인만의 강연·저술과 연구 논문에서 관찰되는 재표현, 독립 모델, 직접 계산, 근사 관리, 판별 가능한 검증과 자기기만 방지 행동을 AI가 실제 작업에서 수행하도록 지시합니다.

> **핵심 주장 범위**
>
> AI가 파인만과 동일한 내면 사고를 한다고 주장하지 않습니다. 검증할 수 있는 것은 AI가 문제를 현상으로 바꾸고, 모델을 만들고, 직접 점검하고, 경쟁 설명을 공격하고, 실패에 따라 결론을 수정하는지입니다.

## 빠른 사용

```text
$feynman-thinking을 사용해 이 제안서를 검토해.
보고서 항목을 채우기 전에 실제 분석과 검증을 수행하고,
이름을 현상으로 바꾼 뒤 독립 모델·직접 점검·경쟁 설명·실패 조건과
수정된 결론을 보여줘.
```

## 설치

현재 프로젝트에 설치:

```bash
npx skills add Ronaldony/feynman-thinking --skill feynman-thinking -a codex
```

전역 설치:

```bash
npx skills add Ronaldony/feynman-thinking --skill feynman-thinking -g -a codex
```

설치 확인:

```bash
npx skills list -g -a codex
```

수동 설치는 `skills/feynman-thinking/` 폴더를 다음 위치 중 하나에 복사합니다.

```text

$HOME/.agents/skills/feynman-thinking/
```

설치 후 새 Codex 세션을 열고 `$feynman-thinking`으로 명시 호출할 수 있습니다.

## 왜 필요한가

유창한 답도 다음 문제를 가질 수 있습니다.

- 전문용어와 권위 있는 인용이 실제 작동 원리를 대신합니다.
- 사실, 추론, 가정과 선호가 한 문장에 섞입니다.
- 첫 설명만 검토하고 다른 메커니즘을 제외합니다.
- 평균·정확도·성장률 같은 한 숫자를 전체 현상으로 오인합니다.
- 계산이나 실행 검사가 가능한데 방법만 제안합니다.
- 반대 증거를 한계 문단에 격리하고 핵심 결론은 바꾸지 않습니다.
- 자료가 부족한데도 확신을 높여 공백을 덮습니다.

`feynman-thinking`은 이를 다음 작업으로 바꿉니다.

```text
이름 제거 → 독립 모델 → 현실 점검 → 판별 공격 → 실패 후 수정
```

## 파인만 핵심 루프

### 1. 이름을 벗깁니다

문제를 용어가 아니라 실제 대상, 입력, 출력, 상태 변화, 관찰량, 환경과 제약으로 다시 씁니다. `좋다`, `효율적이다`, `안전하다` 같은 표현을 관찰 가능한 성공·실패 기준으로 바꿉니다.

### 2. 내 모델을 만듭니다

기존 설명을 반복하기 전에 최소 작동 모델을 만들고, 자연어 과정·수식·기하·인과 그래프·상태 전이·기준선·장난감 모델 중 다른 표현을 검토합니다. 최소 모델과 경쟁 모델이 서로 다른 예측을 내는지 확인합니다.

### 3. 현실에 닿습니다

문제에 관련 있는 직접 점검을 실제로 수행합니다.

- 단위·차원·부호·규모 계산
- 가장 작은 사례와 경계·극한
- 손계산·기준 구현·실행 가능한 테스트
- 실제 데이터·1차 출처·측정과 비교
- 시간·메모리·비용·자원 증가 확인

해당하지 않는 검사는 억지로 만들지 않고 `N/A`와 이유를 남깁니다.

### 4. 모델을 공격합니다

“이 모델이 맞다면 무엇이 관찰되어야 하는가?”, “경쟁 설명과 어디서 달라지는가?”, “어떤 결과가 나오면 이 결론을 버릴 것인가?”를 묻습니다. 여러 모델이 같은 결과를 내면 `판별력 부족`으로 표시합니다.

### 5. 고치고 설명합니다

실패가 자료, 계산, 정의, 가정, 표현, 모델, 적용 범위 또는 구현 중 어디를 공격하는지 찾고 그 층을 수정합니다. 쉬운 설명과 정밀한 근거가 일치하는지 확인한 뒤, 현재 결론과 결론 변경 조건을 전달합니다.

## “보고서 작성”보다 “작업 수행”이 우선입니다

이 버전의 가장 중요한 규칙은 다음입니다.

> 템플릿과 상태 꼬리표는 작업을 기록하는 도구일 뿐, 계산·검색·검사·비교를 대신하지 않는다.

따라서 다음은 스킬 사용으로 인정하지 않습니다.

- `[FACT]`라고 썼지만 출처나 계산을 확인하지 않음
- 대안 모델이라는 제목 아래 같은 설명을 반복함
- 검사를 나열했지만 가능한 검사를 실제로 수행하지 않음
- 어떤 결과가 나와도 결론이 바뀌지 않음
- 불리한 증거를 언급하고도 본문 결론을 수정하지 않음
- 모든 문제에 수식·근사 원장·장난감 모델을 강제로 추가함

## 지식 상태

혼동 위험이 있는 핵심 진술에만 다음 표기를 사용합니다.

| 표기 | 뜻 |
|---|---|
| `[FACT]` | 출처·관찰·실행·계산으로 확인됨 |
| `[INFER]` | 확인된 사실에서 도출한 추론 |
| `[ASSUME]` | 진행을 위해 둔 가정 |
| `[CHOICE]` | 목표·가치·우선순위에 따른 선택 |
| `[UNKNOWN]` | 현재 자료나 도구로 확인할 수 없음 |
| `[CONFLICT]` | 자료·모델·결과가 충돌함 |

확신은 `높음 / 중간 / 낮음`과 이유로 표현합니다. 교정 근거가 없는 수치 확률은 만들지 않습니다.

## 작업 깊이

| 수준 | 상황 | 최소 수행 |
|---|---|---|
| `L0` | 단순·저위험·쉽게 수정 가능 | 현상 재표현, 직접 점검 1개, 변경 조건 |
| `L1` | 일반 분석·설계 | 핵심 루프, 최소 모델, 경쟁 설명, 주요 검증 |
| `L2` | 중요 결정·복합 연구 | 대안 표현, 근사 원장(해당 시), 정량 검사, 자기비판 |
| `L3` | 고위험·고비용·비가역 | 독립 검증, 재현 기록, 최신 권위 자료, 전문가 검토 필요성 |

기본은 `L1`이며 오류 영향과 비가역성이 크면 자동으로 높입니다.

## 요청 예시

### 연구·인과

```text
$feynman-thinking L2로 이 연구의 인과 결론을 검토해.
변수를 인과 구조로 다시 표현하고, 자기선택·역인과·누락 변수라는
경쟁 모델을 구별할 검사를 설계해. 자료로 가능한 검사는 직접 수행해.
```

### 소프트웨어·성능

```text
$feynman-thinking으로 “두 배 빠르다”는 주장을 검증해.
정확성 동치, 입력 크기, 캐시, p95/p99, 메모리와 기준 구현을 확인하고
전면 배포·canary·보류 중 하나를 조건부로 결정해.
```

### 설계·공학

```text
$feynman-thinking L2로 이 아키텍처를 상태 전이로 재표현해.
정상 경로가 아니라 가장 작은 장애 시점을 넣어 단일 장애점과
중복·유실 조건을 찾아 실제 수정안을 제안해.
```

### 설명·학습

```text
$feynman-thinking으로 이 개념을 전문용어 없이 설명해.
단, 쉬운 비유가 빠뜨리는 인과 단계·조건·근사 범위를 정밀 설명과 대조해.
```

## 결과에서 받는 것

작업 규모에 따라 압축되지만 다음 요소를 보존합니다.

1. 실제로 답한 문제와 현재 결론
2. 작동 메커니즘과 선택한 표현
3. 수행한 계산·경계 사례·자료 비교·실행 검사
4. 사실·추론·가정·근사·미검증 항목
5. 경쟁 설명과 다른 예측
6. 불리한 증거가 결론에 미친 실제 영향
7. 적용 범위·실패 조건·결론 변경 조건
8. 가장 작은 다음 판별 행동

모든 항목을 기계적으로 출력하지 않습니다. 짧은 과제에서는 치명적인 검사와 결론만 남깁니다.

## 행동 평가

이 저장소는 정적 형식 검사와 실제 모델 행동 평가를 구분합니다.

### 정적 검사

```bash
cd skills/feynman-thinking
python scripts/validate_skill.py
```

이는 frontmatter, 링크, 평가 데이터와 Python 문법을 검사합니다. AI가 실제로 스킬을 따르거나 결과가 좋아졌음을 증명하지는 않습니다.

### A/B/C 행동 평가

동일한 held-out 과제를 다음 조건에서 실행합니다.

- `baseline`: 추가 사고 지침 없음
- `generic`: 일반 비판적 사고 지침
- `feynman`: `$feynman-thinking` 명시 호출

```bash
cd skills/feynman-thinking
python scripts/run_evals.py --conditions baseline generic feynman --repeats 1
python scripts/grade_evals.py --run-dir evals/results/<run-id>
```

실행기는 `codex exec --json` trace와 최종 답변을 보존합니다. 채점기는 일반 품질과 다음 파인만 특이 지표를 따로 집계합니다.

- 명칭을 관찰 가능한 현상으로 해체했는가?
- 독립적인 대안 표현이 새 구조를 드러냈는가?
- 숫자·경계·장난감 사례·직접 실행으로 현실에 닿았는가?
- 경쟁 모델을 구별하는 검사를 만들었는가?
- 불리한 증거에 따라 결론을 수정했는가?

모델 보조 채점은 최종 진실이 아닙니다. 개별 trace와 채점 근거를 함께 검토해야 합니다.

## 학술적 귀속

규칙의 근거를 세 층으로 구분합니다.

- **[E] 명시 근거**: 파인만이 강연·저술에서 직접 설명한 의심, 불확실성과 과학적 진실성
- **[P] 논문 실천 근거**: 연구 논문에서 관찰되는 직접 계산, 재표현, 근사·보정, 실험 비교와 열린 문제 관리
- **[X] 현대적 확장**: 위험 기반 깊이, 소프트웨어 테스트, 정책 윤리 가드레일과 A/B/C 평가 체계

자세한 근거와 일반화 한계는 [학술 근거 지도](skills/feynman-thinking/references/evidence-base.md)에 기록되어 있습니다.

## 이 스킬이 하지 않는 일

- 파인만의 말투·성격·일화·인용을 모사하지 않습니다.
- 널리 알려진 학습용 4단계만 수행하는 도구가 아닙니다.
- 모든 문제를 첫 원리나 반증 하나로 처리하지 않습니다.
- 근거가 없는데 수치 확률이나 사실을 만들지 않습니다.
- 실험, 실행 환경, 최신 자료 또는 전문가 검토를 말로 대체하지 않습니다.
- 인간·사회 문제를 물리학 변수 몇 개로 과도하게 환원하지 않습니다.
- 스킬 이름만으로 성능 향상이 검증됐다고 주장하지 않습니다.
