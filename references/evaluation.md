# 스킬 평가와 회귀 테스트

스킬의 이름이나 그럴듯함이 아니라 실제 작동을 평가한다. 평가는 `발동 정확도`, `과정 준수`, `결과 품질`, `효율`로 나눈다.

## 1. 발동 평가

[evals/trigger-cases.csv](../evals/trigger-cases.csv)의 프롬프트를 사용한다.

- `should_trigger=yes`: 명시 호출 또는 복잡한 분석·검증 작업
- `should_trigger=no`: 단순 편집, 번역, 파인만 전기·말투 모사 등

오탐과 미탐을 따로 기록하고 `SKILL.md`의 description을 수정한다.

## 2. 결과 품질 루브릭

각 항목을 0~2점으로 평가한다.

| 항목 | 0점 | 1점 | 2점 |
|---|---|---|---|
| 문제 계약 | 목표·성공 기준 없음 | 일부만 명시 | 결정·범위·성공·위험 명확 |
| 실체·메커니즘 | 용어 반복 | 일부 과정 설명 | 입력·상태·관계·출력 명확 |
| 표현·모델 | 첫 표현에 고착 | 대안 언급 | 대안 표현·모델을 비교해 선택 |
| 근사 정직성 | 근사 숨김 | 근사 언급 | 정확 기준·버린 정보·범위·오차 기록 |
| 판별 검증 | 지지 사례만 제시 | 일반 반론 | 경쟁 모델을 구별하는 검사 수행 |
| 불리한 증거 | 누락 | 한계만 형식적 언급 | 실패·충돌이 결론을 실제 수정 |
| 불확실성 교정 | 과도한 확신 | 모호한 주의 문구 | 확신·근거·변경 조건 연결 |
| 실행 가능성 | 결론만 제시 | 일반적 다음 단계 | 구체적 실행 또는 다음 판별 검사 |

총점만 보지 말고 0점 항목을 회귀 실패로 취급한다.

## 3. 필수 회귀 검사

다음 실패가 다시 나타나지 않는지 확인한다.

- 파인만의 이름을 증명으로 사용한다.
- 모든 문제를 첫 원리 환원이나 반증으로만 처리한다.
- 근사와 정확한 사실을 같은 문장에 섞는다.
- 반대 증거를 별도 면책 문구로만 두고 결론은 수정하지 않는다.
- 인간·사회 문제에서 이해관계자와 윤리를 삭제한다.
- 저위험 작업에서 과도한 보고서를 생성한다.
- 고위험 작업에서 최신 자료·전문 검토 필요성을 생략한다.

## 4. 비교 평가

동일 과제를 다음 두 조건으로 수행한다.

1. 스킬 미사용
2. 이 스킬 사용

다음을 비교한다.

- 사실 오류와 논리 오류 수
- 숨은 가정 탐지 수
- 반대 증거 포함률
- 근사·적용 범위 표기율
- 사용자가 재검토 가능한 정도
- 토큰·시간·도구 호출 비용
- 최종 의사결정의 변화와 유용성

스킬 사용이 품질을 높이지 않거나 비용 대비 효과가 낮으면 규칙을 줄이거나 수정한다.

## 5. 버전 관리

실제 실패 사례를 발견하면 다음을 남긴다.

```text
프롬프트:
기대 행동:
실제 행동:
실패 원인:
수정한 규칙:
새 회귀 검사:
```

느낌에 따라 버전을 올리지 말고, 최소한 하나의 실패가 해결되었거나 명확한 기능이 추가되었을 때 변경한다.
