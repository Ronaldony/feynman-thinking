# feynman-thinking 사용 가이드

복잡한 문제를 **그럴듯한 설명**에서 **검토 가능한 문제 정의·모델·증거·검증 기록**으로 바꾸는 Agent Skill입니다.

리처드 파인만의 말투나 성격을 흉내 내는 도구가 아닙니다. 그의 논문과 과학관에서 반복해서 드러나는 **문제의 재표현, 직접적인 메커니즘 탐색, 정확식과 근사의 구분, 판별 가능한 검증, 불리한 증거 공개**를 연구·분석·설계·예측·의사결정 작업에 적용합니다.

> **빠른 사용 예시**
>
> `$feynman-thinking을 사용해 이 제안서를 검토해. 실제로 해결해야 할 문제를 다시 정의하고, 사실·가정·미지를 분리한 뒤, 경쟁 설명과 실패 조건을 검증해. 마지막에는 현재 가장 견고한 결론과 그 결론을 바꿀 증거를 알려줘.`

## 1. 설치하기

가장 간단한 설치 방법입니다.

```bash
npx skills add Ronaldony/feynman-thinking --skill feynman-thinking -a codex
```

스킬을 전역으로 설치하는 경우

```bash
npx skills add Ronaldony/feynman-thinking --skill feynman-thinking -g -a codex
```

설치된 스킬 확인:

```bash
npx skills list -g -a codex
```

현재 프로젝트에만 설치할 때는 `-g`를 빼세요. 수동으로 설치하려면 이 저장소의 `skills/feynman-thinking/` 폴더를 다음 위치 중 하나에 복사합니다.

```text
<repository-root>/.agents/skills/feynman-thinking/
$HOME/.agents/skills/feynman-thinking/
```

설치 후 Codex를 다시 시작하거나 새 세션을 열어 반영을 확인합니다.

## 2. 요청하기

보통은 원하는 작업을 자연어로 요청하면 됩니다.

```text
이 연구 보고서의 핵심 결론이 실제 근거보다 강한지 검증해줘.
```

```text
이 시스템 설계를 파인만식으로 분해하고, 숨은 가정·단일 장애점·실패 조건을 찾아줘.
```

```text
두 전략 중 하나를 골라야 해. 각 전략이 맞으려면 무엇이 참이어야 하는지와 결론을 바꿀 증거를 보여줘.
```

스킬이 자동으로 선택되지 않거나 반드시 이 절차를 적용하고 싶다면 요청 앞에 `$feynman-thinking`을 붙입니다.

```text
$feynman-thinking을 사용해 이 주장에 대한 경쟁 가설과 판별 검사를 설계해줘.
```

분석 깊이도 직접 지정할 수 있습니다.

```text
$feynman-thinking L2로 검토해. 근사 원장, 반대 증거, 민감도와 실패 조건까지 포함해줘.
```

## 3. 이 스킬이 해결하는 문제

다음과 같은 상황에서는 답이 유창해도 결과가 견고하지 않을 수 있습니다.

- 전문용어나 권위 있는 인용이 실제 작동 원리를 대신합니다.
- 확인된 사실, 추론, 가정과 선호가 한 문장 안에 섞여 있습니다.
- 첫 번째로 떠오른 설명만 검토하고 경쟁 설명을 제외합니다.
- 모델의 근사, 생략한 변수와 적용 범위를 숨깁니다.
- 결론을 지지하는 사례는 모으지만 결론을 깨는 증거는 찾지 않습니다.
- 자료가 부족한데도 확신 수준을 높여 빈틈을 덮습니다.

`feynman-thinking`은 이 문제를 다음과 같이 바꿉니다.

| 사용자가 제공하는 것 | 스킬이 수행하는 변환 | 사용자가 받는 결과 |
| --- | --- | --- |
| 질문, 주장, 문서, 설계안, 코드, 선택지 | 문제 재정의 → 지식 상태 분리 → 모델 구성 → 판별 검증 → 자기비판 | 결론, 핵심 근거, 가정, 대안, 검증 결과, 실패 조건, 불확실성, 다음 검사 |
| 복잡한 용어와 설명 | 입력·출력·상태 변화·인과 관계로 재표현 | 실제로 무엇이 어떻게 작동하는지에 대한 설명 |
| 하나의 유력한 해법 | 경쟁 모델과 기준선 비교 | 왜 이 해법이 더 나은지 또는 아직 결정할 수 없는 이유 |
| 근사적 계산이나 예측 | 정확한 출발점, 근사 지점, 오차와 유효 범위 추적 | 어디까지 믿을 수 있고 어디에서 깨지는지에 대한 경계 |

## 4. 구체적으로 무엇을 해주는가

### 문제를 다시 정의합니다

사용자가 처음 제시한 문장을 그대로 풀기 전에 실제 결정, 성공 기준, 범위, 제약과 오류 비용을 확인합니다. 잘못 설정된 문제를 정교하게 푸는 일을 피합니다.

### 사실·추론·가정·미지를 분리합니다

필요할 때 핵심 진술을 다음과 같이 표시합니다.

| 표기 | 뜻 |
| --- | --- |
| `[FACT]` | 출처·관찰·계산으로 확인된 내용 |
| `[INFER]` | 확인된 사실에서 도출한 추론 |
| `[ASSUME]` | 작업을 진행하기 위해 둔 가정 |
| `[CHOICE]` | 목표·가치·우선순위에 따른 선택 |
| `[UNKNOWN]` | 현재 자료나 도구로 확인할 수 없는 내용 |
| `[CONFLICT]` | 자료·모델·결과가 서로 충돌하는 상태 |

자료가 없으면 사실을 만들어 내지 않고, 무엇이 필요한지와 왜 필요한지를 표시합니다.

### 문제에 맞는 표현과 모델을 찾습니다

자연어 설명만 고집하지 않습니다. 필요하면 수식, 흐름도, 인과 그래프, 상태 전이, 장난감 모델 또는 기준선을 사용합니다. 항상 가장 근본적인 이론만 찾는 대신 목적과 관찰량에 맞는 설명 수준을 선택합니다.

### 정확한 관계와 근사를 구분합니다

근사가 들어간 위치, 버린 정보, 적용 가능한 범위, 오차와 실패 신호를 추적합니다. 변수를 제거하더라도 그 영향까지 사라졌다고 가정하지 않습니다.

### 경쟁 설명을 구별할 검사를 만듭니다

“이 설명이 맞다면 무엇이 관찰되어야 하는가?”를 묻고, 경쟁 설명도 같은 결과를 예측하는지 확인합니다. 여러 설명이 똑같은 결과를 내면 그 검사는 `판별력 부족`으로 표시합니다.

### 결론을 공격한 뒤 수정합니다

단순히 장단점을 나열하지 않습니다. 반례, 경계 조건, 독립 유도, 실제 데이터, 기준선, 민감도, 자원 비용처럼 주장 유형에 맞는 검사를 수행하고, 실패하면 결론뿐 아니라 문제 정의·표현·가정·모델까지 되돌아갑니다.

## 5. 언제 사용하면 좋은가

| 작업 | 요청 예시 | 중점 결과 |
| --- | --- | --- |
| 연구·보고서 검증 | `이 논문의 결론이 자료에서 실제로 도출되는지 검증해줘.` | 주장-근거 연결, 대안 설명, 불일치, 추가 실험 |
| 제품·시스템 설계 | `이 아키텍처의 가정과 실패 모드를 공격적으로 검토해줘.` | 요구사항 추적, 병목, 단일 장애점, 스트레스 조건 |
| 소프트웨어 분석 | `이 구현이 맞다는 주장을 독립적인 테스트 관점에서 확인해줘.` | 기준 구현, 경계 입력, 속성 테스트, 자원 증가 |
| 예측·전략 | `이 전망의 기준선, 민감도와 틀렸음을 알 수 있는 신호를 정리해줘.` | 경쟁 시나리오, 교정, 업데이트 규칙 |
| 중요 의사결정 | `선택지 A와 B의 숨은 전제와 되돌릴 수 없는 위험을 비교해줘.` | 트레이드오프, 가역성, 결론 전환 조건 |
| 설명·학습 | `전문용어 없이 설명하되, 빠진 인과 단계와 근사도 함께 보여줘.` | 쉬운 설명과 정밀한 설명의 동시 제공 |
| 자기비판 | `내 초안에서 내가 보고 싶은 증거만 골랐는지 검토해줘.` | 선택 편향, 과도한 확신, 누락된 반례 |

## 6. 주장에 따라 검증 방법을 바꿉니다

모든 문제를 “반례 하나 찾기”로 처리하지 않습니다.

| 주장 유형 | 우선 확인하는 것 |
| --- | --- |
| 사실·최신 정보 | 1차 출처, 날짜·버전, 독립 출처, 인용이 원주장을 실제로 지지하는지 |
| 경험·인과 주장 | 측정, 대조, 재현, 교란 요인, 역인과, 대안 설명 |
| 수학·논리 | 전제, 단계별 유도, 독립 유도, 동치성, 특수·경계 사례 |
| 근사 모델 | 기준해, 단위·차원, 극한, 오차·상한, 보정항, 적용 영역 |
| 소프트웨어·공학 | 단위·통합·속성 테스트, 실패 입력, 스트레스 조건, 안전 여유, 자원 측정 |
| 예측 | 기준선, 시간 분리 검증, 교정, 민감도, 시나리오와 업데이트 규칙 |
| 정책·사회 판단 | 인과 가정, 이해관계자, 인센티브, 분배 효과, 윤리와 실행 가능성 |

검사 결과는 가능한 경우 `통과`, `실패`, `미검증`, `판별력 부족`, `범위 밖`으로 구분합니다.

## 7. 어떤 결과를 받게 되는가

작업 규모에 따라 압축되지만, 기본 결과는 다음 구조를 따릅니다.

1. **문제 재정의** — 실제로 답해야 할 질문과 성공 기준
2. **현재 결론** — 가장 견고한 판단과 확신 수준
3. **지식 상태** — 사실, 추론, 가정, 선택, 미지와 충돌
4. **작동 모델** — 핵심 변수와 관계, 선택한 표현
5. **근사와 적용 범위** — 생략한 것, 오차, 깨지는 조건
6. **경쟁 설명 또는 대안** — 다른 모델이 설명하는 범위
7. **검증 기록** — 수행한 검사와 통과·실패·미검증 항목
8. **자기비판** — 결론에 불리한 증거와 남은 취약점
9. **결론을 바꿀 증거** — 다음에 무엇을 확인해야 하는지
10. **실행 단계** — 지금 할 수 있는 가장 작은 다음 조치

따라서 결과는 단순히 “정답은 A입니다”로 끝나지 않습니다. **왜 A인지, 어디까지 A인지, 무엇이 나오면 A를 버려야 하는지**까지 설명하는 것을 목표로 합니다.

## 8. 작업 깊이

스킬은 오류의 영향과 되돌릴 수 있는 정도에 맞춰 검증 깊이를 조정합니다.

| 수준 | 적합한 상황 | 수행 범위 |
| --- | --- | --- |
| `L0` | 단순하고 쉽게 수정 가능한 작업 | 핵심 사실 확인, 중요한 가정 표시 |
| `L1` | 일반 분석·설계 | 작동 모델, 핵심 근거, 주요 한계 또는 반례 |
| `L2` | 중요한 결정·복합 연구 | 대안 모델, 근사 원장, 정량 검사, 반대 증거, 민감도·실패 조건 |
| `L3` | 고위험·고비용·비가역 작업 | 독립 검증, 재현 가능한 기록, 보수적 결론, 전문가 검토 필요성 |

기본은 `L1`입니다. 짧은 답을 원하면 `L0`, 논문 검토나 중요한 설계 결정에는 `L2`, 의료·법률·안전·대규모 비용처럼 오류 비용이 큰 문제에는 `L3`를 요청하세요.

## 9. 이 스킬이 하지 않는 일

- 파인만의 말투, 성격, 일화나 인용문을 모사하는 역할이 아닙니다.
- 널리 알려진 “파인만 학습법”의 암기용 4단계만 수행하는 도구가 아닙니다.
- 모든 문제에서 무조건 첫 원리부터 다시 유도하지 않습니다.
- 근거가 없는데 수치 확률이나 확신을 만들어 내지 않습니다.
- 긴 체크리스트를 적용했다는 사실을 이해나 진실의 증거로 취급하지 않습니다.
- 실험, 실제 데이터, 실행 환경 또는 도메인 전문가가 필요한 작업을 말만으로 대체하지 않습니다.
- 인간·사회 문제를 물리학 변수 몇 개로 과도하게 축소하지 않습니다.

고위험 분야에서는 이 스킬의 구조화된 검토가 전문 진단·법률 판단·안전 인증을 대신하지 않습니다. 필요한 전문 기준과 실제 검증을 함께 사용해야 합니다.

## 10. ‘파인만식’이라는 이름의 근거

이 스킬은 파인만이 직접 발표한 하나의 고정 체크리스트를 복원했다고 주장하지 않습니다. 규칙의 근거를 세 층으로 구분합니다.

- **[E] 명시 근거**: 파인만이 강연·교육 자료에서 직접 설명한 의심, 불확실성, 과학적 진실성
- **[P] 논문 실천 근거**: 1939~1986년 연구 논문에서 관찰되는 재표현, 직접 계산, 동치성, 근사·보정, 실험 비교, 열린 문제 관리
- **[X] 현대적 확장**: 소프트웨어 테스트, 위험 기반 검증 수준, 정책·사회 문제의 윤리 가드레일처럼 일반 작업을 위해 추가한 규칙

파인만의 이름은 권위를 빌리기 위한 장식이 아니라 **스킬 자체도 반례와 실제 성능 평가를 받아야 한다는 제약**으로 사용합니다. 근거와 일반화 한계는 [학술 근거 지도](references/evidence-base.md)에서 확인할 수 있습니다.

## 11. 문제 해결

### 스킬이 자동으로 선택되지 않습니다

요청 맨 앞에 명시적으로 호출합니다.

```text
$feynman-thinking을 사용해 ...
```

### 분석이 너무 얕습니다

원하는 깊이와 필수 산출물을 지정합니다.

```text
L2로 분석하고 경쟁 모델, 근사 원장, 정량 검사, 반대 증거와 결론 전환 조건을 포함해줘.
```

### 답이 너무 깁니다

검증 범위를 유지하면서 출력만 압축하도록 요청합니다.

```text
L1로 검토하되 결론, 핵심 근거 3개, 가장 큰 가정과 실패 조건만 보여줘.
```

### 필요한 자료가 없습니다

자료가 없는 상태에서 결론을 단정하게 하지 말고, 미확인 항목과 가장 판별력 있는 다음 자료를 요청합니다.

```text
확인할 수 없는 내용은 [UNKNOWN]으로 남기고, 결론을 가장 크게 바꿀 자료부터 알려줘.
```

## 13. 저장소 검증

저장소를 수정하거나 기여할 때 스킬 폴더에서 다음 명령을 실행합니다.

```bash
python scripts/validate_skill.py
```

공식 `skills-ref` 도구가 설치되어 있다면 추가로 실행합니다.

```bash
skills-ref validate .
```

설치 후보 탐색도 확인할 수 있습니다.

```bash
npx skills add . --list
```
