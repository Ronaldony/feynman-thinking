# 상세 작업 흐름

이 문서는 L2~L3 작업, 스킬 자체 개정, 또는 사용자가 전체 검증 기록을 요구할 때 읽는다. 모든 절차를 의례적으로 채우지 말고 **결론을 바꿀 수 있는 실제 작업**에 자원을 집중한다.

## 0. 작업 원칙

1. 보고서보다 작업이 먼저다.
2. 제목과 태그는 계산·조사·테스트를 대신하지 않는다.
3. 가능한 검사는 수행하고, 수행할 수 없는 검사는 `미검증`으로 남긴다.
4. 적용되지 않는 항목은 `해당 없음(N/A)`으로 두되 이유를 적는다.
5. 실패한 검사는 결론·모델·범위·확신 중 적어도 하나를 바꿔야 한다.
6. 사용자에게는 비공개 사고 전체가 아니라 전제, 핵심 유도, 계산, 출처, 검사와 수정 결과를 제공한다.

## 1. 문제 계약

### 1.1 실제 문제를 찾는다

다음 세 문장을 작성한다.

1. 사용자가 표면적으로 요구한 것
2. 실제로 결정·설명·예측·제작해야 하는 것
3. 잘못 답했을 때 발생하는 손실과 되돌릴 수 있는 정도

### 1.2 성공 기준을 관찰 가능하게 만든다

`좋다`, `견고하다`, `효율적이다`, `안전하다`는 판정 기준이 아니다. 가능한 경우 다음 중 하나로 바꾼다.

- 수치와 허용 범위
- 통과·실패 조건
- 사용자의 관찰 가능한 행동
- 재현 가능한 테스트
- 비교 기준선
- 의사결정 마감과 롤백 조건

### 1.3 모호성을 처리한다

- 결과를 크게 바꾸는 모호성만 확인한다.
- 나머지는 합리적 가정을 세우고 `[ASSUME]`으로 표시한다.
- 가정별로 결론이 달라지면 분기 시나리오를 만든다.
- 최신 사실과 고위험 사실은 가정하지 말고 권위 자료로 확인한다.

## 2. 이름을 벗긴 현상 지도

문제를 다음 요소로 다시 쓴다.

| 요소 | 질문 |
|---|---|
| 대상 | 실제로 관찰·조작·결정하는 것은 무엇인가? |
| 상태 | 어떤 속성이 시간 또는 조건에 따라 달라지는가? |
| 입력 | 무엇이 계에 들어오는가? |
| 출력 | 무엇을 측정하거나 얻는가? |
| 관계 | 무엇이 무엇에 어떤 방향으로 영향을 주는가? |
| 환경 | 모델 밖 조건이 결과에 어떤 흔적을 남기는가? |
| 제약 | 물리·논리·법·비용·시간 중 바꿀 수 없는 것은 무엇인가? |
| 미지 | 현재 확인하지 못한 핵심은 무엇인가? |
| 판정 | 어떤 관찰이 성공과 실패를 구별하는가? |

핵심 명사를 작동 정의로 바꾼다.

```text
“빠르다” → 어떤 입력 분포에서 어느 지연시간 지표가 기준선보다 얼마나 낮은가
“안전하다” → 어떤 고장·부하·환경에서 허용 손실을 넘지 않는가
“효과가 있다” → 무엇을 바꾸었을 때 어떤 결과가 얼마나 달라지는가
```

## 3. 내 모델과 대안 표현

### 3.1 잠정 최소 모델

권위 있는 해석을 반복하기 전에 문제를 설명하는 가장 작은 작동 모델을 만든다. 단, 사실 검증이 먼저 필요한 최신·법률·의료·안전 정보는 권위 자료를 우선한다.

최소 모델은 다음을 포함한다.

- 핵심 변수 또는 구성 요소
- 입력에서 출력까지의 작동 경로
- 모델이 설명해야 하는 관찰량
- 모델이 맞다면 달라져야 하는 결과
- 적용 범위

단순하다는 이유만으로 채택하지 않는다. 관찰량을 설명하고 판별 가능한 결과를 내야 한다.

### 3.2 표현 탐색

다음 중 적절한 표현 두 개를 짧게 비교한다.

- 작동 과정의 자연어 설명
- 변수와 관계식
- 흐름도 또는 상태 전이표
- 인과 그래프
- 공간·시간 도식
- 가장 작은 사례
- 장난감 모델
- 기준선·무효 모델
- 코드·시뮬레이션·프로토타입

선택 기준:

1. 숨은 가정을 드러내는가?
2. 관련 없는 자유도를 줄이는가?
3. 귀결을 쉽게 도출하는가?
4. 독립 검증이 가능한가?
5. 현실과의 연결을 보존하는가?

표현을 바꾸자 결론이 달라지면 동치성 가정이 깨진 것이다. 무엇을 생략했는지 추적한다.

### 3.3 경쟁 모델

최소한 다음 중 하나를 둔다.

- 기존 통념 또는 기준선
- 반대 인과 방향
- 누락 변수 설명
- 더 단순한 무효 모델
- 측정·표본·선택 편향 설명
- 더 현실적인 복합 모델

경쟁 모델은 장식적인 “다른 관점”이 아니라 같은 관찰을 실제로 설명할 수 있어야 한다.

## 4. 계산·관찰로 내려가기

L1 이상에서는 최소 하나의 구체적 작업 증거를 만든다. 사용 가능한 자료와 도구에 맞춰 가장 싼 고정보량 검사를 먼저 한다.

### 4.1 가능한 작업 증거

- 독립적인 유도
- 단위·차원 확인
- 규모 또는 페르미 추정
- 부호·방향 확인
- 0, 1, 무한대, 최대·최소 같은 경계 사례
- 가장 작은 반례 또는 장난감 입력
- 기준 구현과 코드 실행
- 단위·속성·통합·스트레스 테스트
- 표 또는 간단한 계산 시트
- 1차 출처의 날짜·버전·원문 확인
- 인과 그래프와 교란 경로
- 측정·실험·프로토타입과 사전 통과 기준

### 4.2 작업 기록

각 작업은 다음 형식으로 남긴다.

```text
확인하려는 주장:
사용한 입력·자료:
수행한 계산·관찰·테스트:
사전 통과 기준:
결과:
판정:
결론에 미친 영향:
```

도구나 자료가 없어 수행하지 못했으면 다음을 기록한다.

```text
상태: 미검증
부족한 입력:
가장 판별력 있는 다음 검사:
그 결과에 따라 바뀔 결론:
```

“테스트가 필요하다”라는 문장만 남기지 않는다.

## 5. 정확한 관계와 근사

근사를 사용하면 다음 질문에 답한다.

1. 정확한 출발점이나 기준선은 무엇인가?
2. 어느 단계에서 근사가 들어갔는가?
3. 무엇을 작다, 느리다, 독립적이다, 선형이다라고 가정했는가?
4. 버린 항·정보·상호작용은 무엇인가?
5. 제거한 환경 효과를 무엇으로 보존했는가?
6. 유효한 매개변수 범위는 어디인가?
7. 오차를 계산, 상한, 민감도, 데이터 비교 중 어떤 방법으로 평가했는가?
8. 근사가 실패할 때 어떤 신호가 나타나는가?
9. 더 정밀한 보정 경로는 무엇인가?

근사가 적용되지 않는 작업에서는 `N/A`로 두고 억지 수치화를 하지 않는다.

## 6. 귀결과 판별 검사

각 모델에 대해 다음을 쓴다.

```text
모델이 맞다면 관찰·계산되어야 하는 것:
경쟁 모델도 같은 결과를 예측하는가:
두 모델이 달라지는 지점:
모델을 약화시키는 결과:
모델을 폐기하거나 범위를 줄일 결과:
```

검사 우선순위:

1. 싸고 치명적인 검사: 정의 모순, 단위, 부호, 작은 반례
2. 핵심 가정을 직접 공격하는 검사
3. 경쟁 모델을 구별하는 검사
4. 정량 오차·민감도·자원 검사
5. 비싼 실험·프로토타입·독립 검토

검사 전에 결과별 행동을 정한다.

| 가능한 결과 | 사전 행동 |
|---|---|
| 현재 모델에 유리 | 확신을 어느 정도 높일지 |
| 경쟁 모델에 유리 | 어떤 가정·모델을 수정할지 |
| 둘 다 설명 | `판별력 부족`으로 낮추고 다음 검사 선택 |
| 적용 범위 밖 | 결론의 범위 축소 |
| 측정 실패 | 자료·도구 문제로 분리 |

## 7. 수정 루프

검증 실패를 다음 층으로 분류한다.

- 자료 실패
- 계산 실패
- 정의 실패
- 가정 실패
- 표현 실패
- 모델 실패
- 적용 범위 실패
- 구현·자원 실패

실패가 발견되면 결론을 방어하지 말고 해당 층을 수정한다.

```text
수정 전 모델·결론:
실패한 검사:
공격받은 층:
수정 내용:
수정 후 모델·결론:
확신 변화와 이유:
남은 취약점:
```

불리한 증거가 있었는데 결론·범위·확신이 전혀 바뀌지 않았다면 자기기만 감사 대상으로 처리한다.

## 8. 쉬운 설명과 정밀한 설명의 동치성

다음 두 설명을 함께 만든다.

1. 전문용어 없이 작동 경로를 설명한 짧은 설명
2. 가정, 변수, 자료, 수식·테스트와 예외를 보존한 정밀한 설명

확인할 것:

- 쉬운 설명이 정밀한 설명의 핵심 인과 단계를 삭제하지 않았는가?
- 비유가 실제 메커니즘과 다른 예측을 만들지 않는가?
- 정밀한 설명이 용어만 늘리고 실제 관계를 흐리지 않는가?
- 어느 지점에서 설명이 막히는가? 그 지점이 미지 또는 숨은 가정인가?

## 9. 반대편 검토

L2 이상에서는 제출 전에 다음을 수행한다.

1. 현재 결론의 핵심 전제를 한 문장으로 쓴다.
2. 그 전제가 틀려도 같은 관찰을 설명할 모델을 만든다.
3. 가장 작은 반례, 가장 불리한 자료, 가장 취약한 경계를 찾는다.
4. 두 모델을 가장 싸고 명확하게 구별하는 검사를 정한다.
5. 실패 결과가 나오면 실제로 무엇을 수정할지 확인한다.
6. 실제 작업 증거가 있는지, 아니면 형식만 채웠는지 감사한다.

자세한 규칙은 [self-critique.md](self-critique.md)를 읽는다.

## 10. 종료 규칙

다음 중 하나이면 현재 작업을 종료한다.

- 성공 기준을 충족하고 중요한 반대 증거를 처리했다.
- 추가 검증의 기대 가치가 비용보다 작다.
- 핵심 정보가 없어 조건부 결론 이상으로 나아갈 수 없다.
- 모델들이 현재 자료에서 구별되지 않으며 다음 판별 검사가 명확하다.

종료는 완전한 지식의 선언이 아니다. 남은 공백을 보존한 채 현재 결정에 충분한 상태를 뜻한다.
