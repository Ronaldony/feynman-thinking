# feynman-thinking

AI가 복잡한 문제를 다룰 때 **리처드 파인만의 말투가 아니라 연구 행동을 모방하도록 유도하는 Agent Skill**입니다.

문제를 그럴듯한 설명으로 마무리하지 않고 다음 작업을 수행합니다.

> **이름을 벗긴다 → 내 모델과 다른 표현을 만든다 → 계산·관찰 가능한 곳까지 내려간다 → 경쟁 모델로 공격한다 → 실패에 맞춰 수정하고 쉽게 설명한다**

이 스킬이 목표로 하는 것은 “파인만처럼 보이는 답변”이 아니라, 사용자가 다시 확인할 수 있는 **문제 정의·모델·유도·계산·테스트·불리한 증거·수정 기록**입니다.

## 설치

현재 프로젝트에 설치:

```bash
npx skills add Ronaldony/feynman-thinking --skill feynman-thinking -a codex
```

사용자 영역에 전역 설치:

```bash
npx skills add Ronaldony/feynman-thinking --skill feynman-thinking -g -a codex
```

수동 설치 시 `skills/feynman-thinking/`을 다음 위치 중 하나에 복사합니다.

```text
<repository-root>/.agents/skills/feynman-thinking/
$HOME/.agents/skills/feynman-thinking/
```

설치 후 Codex를 다시 시작하거나 새 세션을 엽니다.

## 바로 사용하기

명시적으로 적용하려면 요청 앞에 `$feynman-thinking`을 붙입니다.

```text
$feynman-thinking을 사용해 이 알고리즘이 기존보다 두 배 빠르다는 주장을 검증해.
평균값을 반복하지 말고 실제 성능을 좌우하는 변수로 다시 표현한 뒤,
가능한 계산·테스트를 수행하고 경쟁 설명과 배포 중단 조건까지 제시해.
```

분석 깊이를 지정할 수도 있습니다.

```text
$feynman-thinking L2로 이 투자 제안서를 검토해.
사실·추론·가정·선호를 분리하고, 대안 모델과 정량 검사,
불리한 증거가 결론을 어떻게 바꾸는지 보여줘.
```

자연어 요청만으로도 복잡한 검증 과제에서는 암묵적으로 선택될 수 있습니다.

```text
이 연구 결과가 정말 인과관계인지 자기선택과 역인과를 포함한 경쟁 설명을 만들고,
두 설명을 구별할 가장 싼 검사를 설계해줘.
```

## 이 스킬이 모방하는 것

### 1. 이름보다 현상을 본다

`빠르다`, `안전하다`, `효과적이다` 같은 이름을 그대로 사용하지 않습니다.

```text
“두 배 빠르다”
→ 어떤 입력 분포와 하드웨어에서
→ 평균, p95, p99 중 어느 지연시간이
→ 어느 기준 구현보다 얼마나 낮고
→ 정확성과 메모리는 유지되는가
```

### 2. 설명을 복사하기 전에 작동 모델을 만든다

권위 있는 용어를 반복하는 대신 입력이 어떤 과정을 거쳐 출력이 되는지 최소 모델을 만듭니다. 필요하면 수식, 흐름도, 인과 그래프, 상태 전이, 장난감 사례 또는 기준선으로 표현을 바꿉니다.

### 3. 실제 작업으로 내려간다

가능한 경우 다음 중 적어도 하나를 수행합니다.

- 독립 유도와 작은 계산
- 단위·규모·부호·극한 확인
- 가장 작은 사례나 반례
- 코드 실행, 기준 구현, 테스트, 벤치마크
- 데이터 비교와 인과 도식
- 1차 출처의 날짜·버전·원주장 확인
- 사전 통과 기준이 있는 실험 설계

“테스트가 필요합니다”라는 문장만 쓰고 끝내지 않습니다. 실행할 수 없는 검사는 `미검증`으로 남기고 무엇이 필요하며 결과에 따라 결론이 어떻게 달라지는지 적습니다.

### 4. 지지 사례보다 판별 검사를 찾는다

현재 설명이 맞다면 무엇이 달라져야 하는지 묻습니다. 경쟁 설명도 같은 결과를 예측하면 그 검사는 `판별력 부족`입니다.

### 5. 불리한 결과에 맞춰 되돌아간다

반대 증거를 한계 문단에만 추가하지 않습니다. 실패가 자료, 계산, 정의, 가정, 표현, 모델 또는 적용 범위를 공격하는지 판정하고 그 단계로 돌아가 수정합니다.

## 일반적인 비판적 사고 프롬프트와의 차이

| 일반적인 요청 | feynman-thinking의 추가 행동 |
|---|---|
| 장단점을 분석해줘 | 같은 관찰을 설명하는 경쟁 모델과 판별 검사를 만든다 |
| 쉽게 설명해줘 | 쉬운 설명이 정밀한 모델과 같은 메커니즘을 보존하는지 확인한다 |
| 가정을 찾아줘 | 가정이 틀렸을 때 달라지는 관찰과 수정 규칙을 만든다 |
| 데이터를 검토해줘 | 단위·규모·기준선·경계·선택 편향을 직접 검사한다 |
| 반론을 제시해줘 | 불리한 결과가 결론·범위·확신을 실제로 바꾸게 한다 |

## 결과 예시

다음 주장만 주어졌다고 가정합니다.

```text
단일 벤치마크에서 평균 실행시간이 절반이므로 새 알고리즘은 두 배 빠르다.
```

이 스킬은 이를 다음처럼 처리합니다.

```text
실제 문제:
운영 입력에서 정확성을 유지하면서 지연시간과 자원 사용량이 지속적으로 개선되는가?

[FACT]
특정 벤치마크 한 개에서 평균 실행시간이 절반이었다.

[UNKNOWN]
입력 크기 분포, 캐시 상태, p95·p99 지연시간, 메모리, 출력 동치성.

작동 모델:
실행시간 = f(입력 크기, 입력 분포, 캐시, 동시성, 메모리 제한)

경쟁 설명:
A. 실제 계산량 또는 상수 계수가 개선됐다.
B. 캐시·워밍업이 새 구현에 유리했다.
C. 정확성을 일부 희생했다.
D. 평균은 좋아졌지만 꼬리 지연시간이나 메모리는 악화됐다.

판별 작업:
동일 환경 반복 측정, cold/warm cache 분리, 입력 크기별 곡선,
기준 구현과 출력 동치성, p95·p99와 메모리 측정.

수정된 결론:
현재 자료만으로 “두 배 빠르다”거나 전면 배포가 안전하다고 결론 낼 수 없다.
검사를 통과하면 제한된 canary 배포를 고려하고 롤백 기준을 둔다.
```

핵심은 항목 수가 아니라 **검사 후 결론이 바뀌었다는 점**입니다.

## 지식 상태

필요할 때 핵심 진술을 구분합니다.

| 표기 | 뜻 |
|---|---|
| `[FACT]` | 출처·관찰·실행·계산으로 확인 |
| `[INFER]` | 확인된 사실에서 도출 |
| `[ASSUME]` | 진행을 위해 둔 가정 |
| `[CHOICE]` | 목표·가치·우선순위에 따른 선택 |
| `[UNKNOWN]` | 현재 확인할 수 없음 |
| `[CONFLICT]` | 자료·모델·결과가 충돌 |

확신은 `높음 / 중간 / 낮음`과 이유로 표현합니다. 근거 없는 수치 확률이나 무의미한 정밀도는 만들지 않습니다.

## 작업 깊이

| 수준 | 적합한 상황 | 최소 수행 |
|---|---|---|
| `L0` | 단순하고 쉽게 수정 가능 | 실제 질문으로 재표현, 중요한 가정과 싼 검사 |
| `L1` | 일반 분석·설계·설명 | 5단계 핵심 루프, 작동 모델, 구체적 작업 증거 |
| `L2` | 중요한 결정·복합 연구 | 대안 모델, 근사 원장, 정량·판별 검사, 실제 수정 |
| `L3` | 고위험·고비용·비가역 | 독립 검증, 재현 기록, 보수적 결론, 전문가 검토 |

기본은 `L1`입니다. 오류 비용과 되돌릴 수 있는 정도에 따라 자동으로 높아질 수 있습니다.

## 주장에 따라 검증법을 바꿉니다

모든 문제를 첫 원리나 반례 하나로 처리하지 않습니다.

| 주장 유형 | 우선하는 실제 작업 |
|---|---|
| 사실·최신 정보 | 1차 출처, 날짜·버전과 원주장 직접 확인 |
| 경험·인과 | 측정, 대조, 교란·역인과와 경쟁 인과 그래프 |
| 수학·논리 | 정의·전제, 단계별 유도, 독립 유도와 작은 반례 |
| 근사 모델 | 정확한 기준선, 단위·극한, 오차·상한과 적용 범위 |
| 소프트웨어 | 기준 구현, 실패 입력, 테스트·벤치마크·자원 측정 |
| 설계·공학 | 요구사항, 안전 여유, 스트레스 조건과 고장 모드 |
| 예측 | 기준선, 시간 분리 검증, 교정과 업데이트 규칙 |
| 정책·조직 | 인센티브, 이해관계자, 집단별 효과, 윤리와 실행 가능성 |
| 설명·학습 | 작동 설명, 대안 표현, 작은 예제와 정밀 근거의 일치 |

검사 결과는 `통과`, `실패`, `미검증`, `판별력 부족`, `범위 밖`, `해당 없음(N/A)`으로 구분합니다.

## 이 스킬이 하지 않는 일

- 파인만의 말투·성격·일화·인용문을 연기하지 않습니다.
- 널리 알려진 암기용 “파인만 학습법 4단계”에만 한정되지 않습니다.
- AI의 비공개 내부 사고가 실제 파인만과 같다고 주장하지 않습니다.
- 모든 문제를 무조건 가장 기초 이론부터 다시 유도하지 않습니다.
- 템플릿을 채운 사실을 이해나 정확성의 증거로 취급하지 않습니다.
- 실행하지 않은 테스트를 수행한 것처럼 쓰지 않습니다.
- 인간·사회 문제를 물리 변수 몇 개로 과도하게 축소하지 않습니다.
- 의료·법률·재무·안전의 전문 판단과 실제 검증을 대체하지 않습니다.

## 실제 성능 검증

이 저장소는 스킬의 존재와 형식만 검사하지 않고, 행동 효과를 비교할 수 있는 평가 자산을 포함합니다.

```text
evals/trigger-cases.csv       발동 기대 사례
evals/reasoning-cases.jsonl   도메인별 추론 과제
evals/grading-rubric.json     0/1/2/N/A 채점과 하드 게이트
scripts/run_eval.py           외부 에이전트 반복 실행과 trace 저장
scripts/prepare_blind_review.py 조건을 숨긴 검토 패킷 생성
```

비교 조건은 다음과 같습니다.

1. 스킬 미사용
2. 일반 비판적 사고 지침
3. `feynman-thinking` 명시 호출
4. 스킬 설치 상태의 암묵 호출

이 저장소는 스킬 사용이 자동으로 성능 향상을 보장한다고 주장하지 않습니다. 반복 실행, 블라인드 채점과 일반 비판적 사고 조건과의 비교를 통해 확인해야 합니다.

자세한 프로토콜은 [references/evaluation.md](references/evaluation.md)를 참조하세요.

## 저장소 구조와 정본

배포 정본은 `skills/feynman-thinking/`입니다. 루트의 `SKILL.md`, `agents/`, `assets/`, `evals/`, `references/`, `scripts/`는 저장소 자체를 직접 설치할 수 있도록 둔 배포 미러입니다.

`python scripts/sync_mirror.py`는 정본을 루트로 복사하고, `python scripts/validate_skill.py`는 두 위치가 바이트 단위로 일치하는지 확인합니다. 한쪽만 수정하면 검증이 실패합니다.

## 저장소 검증

```bash
python scripts/sync_mirror.py
python scripts/validate_skill.py
python -m py_compile scripts/*.py
python scripts/run_eval.py --condition all --dry-run
```

공식 `skills-ref` 도구가 설치되어 있다면 추가로 실행합니다.

```bash
skills-ref validate .
```

평가 실행 예:

```bash
python scripts/run_eval.py \
  --condition feynman-explicit \
  --repeats 3 \
  --command "codex exec --json -" \
  --environment "Codex CLI, feynman-thinking installed"
```
