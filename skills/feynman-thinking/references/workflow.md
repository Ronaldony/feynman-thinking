# 상세 실행 흐름

이 문서는 L2~L3 작업, 복합 연구 또는 사용자가 전체 검증 기록을 요구할 때 읽는다. 절차를 의례적으로 모두 채우지 말고 **결론을 바꿀 수 있는 작업**에 자원을 집중한다.

## 0. 실행 원칙

1. 먼저 실제 작업을 수행하고 나중에 보고한다.
2. 문서 제목이나 상태 꼬리표는 증거가 아니다.
3. 가능한 계산·검색·실행·비교를 제안으로 대체하지 않는다.
4. 적용할 필요가 없는 항목은 `N/A`와 이유를 기록한다.
5. 실패가 나오면 결론을 방어하지 말고 실패한 층으로 돌아간다.

## 1. 문제 계약

### 1.1 표면 요청과 실제 결정을 분리한다

다음 세 문장을 작성한다.

1. 사용자가 표면적으로 요구한 것
2. 실제로 결정하거나 만들어야 하는 것
3. 잘못 답했을 때 발생하는 손실

### 1.2 성공 기준을 관찰 가능하게 만든다

`좋다`, `정확하다`, `견고하다`, `효율적이다`는 판정 기준이 아니다. 가능한 경우 다음으로 바꾼다.

- 수치 또는 허용 범위
- 통과·실패 조건
- 사용자의 실제 행동 또는 결정
- 재현 가능한 테스트
- 비교할 기준선

### 1.3 모호성을 처리한다

- 결과를 크게 바꾸는 모호성만 질문하거나 분기한다.
- 나머지는 합리적 가정을 두고 `[ASSUME]`로 표시한다.
- 가정에 따라 결론이 달라지면 시나리오별로 결과를 분리한다.

## 2. 이름을 벗긴다

문제를 한 장의 현상 지도로 바꾼다.

| 요소 | 질문 |
|---|---|
| 대상 | 실제로 관찰·조작·결정하는 것은 무엇인가? |
| 상태 | 어떤 속성이 시간이나 조건에 따라 바뀌는가? |
| 입력 | 무엇이 계에 들어오는가? |
| 출력 | 무엇을 측정하거나 얻게 되는가? |
| 관계 | 무엇이 무엇에 어떤 방향으로 영향을 주는가? |
| 환경 | 모델 밖 조건이 결과에 어떤 흔적을 남기는가? |
| 제약 | 물리·논리·법·비용·시간 중 바꿀 수 없는 것은 무엇인가? |
| 미지 | 현재 결론을 가장 크게 흔드는 미확인 사항은 무엇인가? |

핵심 용어마다 다음 문장을 완성한다.

```text
여기서 ‘___’란, ___을 관찰하거나 조작했을 때 ___의 차이로 판정되는 상태다.
```

이 문장을 만들 수 없으면 용어가 메커니즘을 가리고 있을 가능성이 크다.

## 3. 표현 토너먼트

첫 표현을 곧바로 채택하지 않는다. 최소 두 표현을 짧게 비교한다.

- 작동 과정의 자연어 설명
- 변수와 관계식
- 인과 그래프
- 상태 전이표
- 공간·시간 도식
- 기준선 또는 무효 모델
- 가장 작은 반례
- 장난감 모델
- 시뮬레이션 또는 프로토타입

표현별로 다음을 평가한다.

1. 숨은 가정을 드러내는가?
2. 관련 없는 자유도를 줄이는가?
3. 판별 가능한 귀결을 쉽게 도출하는가?
4. 독립 검증이 가능한가?
5. 현실과의 연결 고리를 보존하는가?

표현이 달라졌는데 결론이 달라지면 둘의 동치성 가정이 깨진 것이다. 어느 표현이 무엇을 생략했는지 추적한다.

## 4. 내 모델을 만든다

### 4.1 최소 모델

결론에 필요한 가장 적은 변수와 관계만 포함한다. 단순하다는 이유만으로 채택하지 않는다. 최소 모델은 다음을 충족해야 한다.

- 핵심 관찰량을 설명한다.
- 입력과 출력 사이의 작동 관계를 제시한다.
- 적어도 하나의 확인 가능한 귀결을 낸다.
- 알려진 경계와 적용 범위를 가진다.

### 4.2 경쟁 모델

최소한 다음 중 하나를 둔다.

- 기존 통념 또는 기준선
- 반대 인과 방향
- 누락 변수 설명
- 선택·측정 편향 설명
- 더 단순한 무효 모델
- 더 현실적인 복합 모델

경쟁 모델이 이름만 다르고 같은 예측을 내면 실제 대안이 아니다.

### 4.3 환경 효과 보존

변수를 제거할 때 효과를 다음 중 하나로 남긴다.

- 경계 조건
- 유효 계수 또는 항
- 제약 조건
- 오차·교란 항
- 외부 영향 시나리오
- 적용 범위 축소

## 5. 근사 원장

근사를 사용한 경우에만 다음 질문에 답한다. 근사가 없는 작업에서는 `N/A`로 처리한다.

1. 정확한 출발점 또는 기준은 무엇인가?
2. 어느 단계에서 근사가 들어갔는가?
3. 무엇을 작다, 느리다, 독립적이다, 선형이다, 정상 상태라고 가정했는가?
4. 버린 항이나 정보는 무엇인가?
5. 유효한 매개변수 범위는 어디인가?
6. 오차를 계산·상한·경험 비교 중 어떤 방식으로 평가했는가?
7. 근사가 실패할 때 어떤 신호가 나타나는가?
8. 더 정밀한 보정 방법은 무엇인가?

## 6. 현실 접촉 사다리

비용이 낮은 것부터 실제로 수행한다.

### 6.1 즉시 검사

- 정의 모순
- 단위와 차원
- 부호와 방향
- 규모 추정
- 0, 1, 최대·최소, 무한대 같은 경계
- 가장 작은 사례

### 6.2 독립 경로

- 다른 표현에서의 유도
- 기준 구현 또는 손계산
- 알려진 특수해·기준선과 비교
- 작은 시뮬레이션이나 프로토타입

### 6.3 현실 자료

- 1차 출처
- 실제 데이터 또는 측정
- 재현 가능한 실행
- 외부 독립 검증
- 도메인 전문가 검토

도구나 자료가 있으면 수행한다. 수행하지 못했으면 결과를 상상하지 말고 `미검증`과 이유를 남긴다.

## 7. 귀결과 판별 검사

각 모델에 대해 다음 형식으로 작성한다.

```text
모델:
모델이 맞다면 관찰·계산되어야 하는 것:
경쟁 모델과 달라지는 지점:
모델을 약화시키는 결과:
모델을 폐기하거나 범위를 줄일 결과:
가장 싼 판별 검사:
```

모든 성공 사례가 판별력 있는 증거는 아니다. 경쟁 모델도 같은 결과를 설명하면 증거의 힘을 낮춘다.

검사 우선순위는 다음과 같다.

1. 싸고 치명적인 검사
2. 핵심 가정을 직접 공격하는 검사
3. 경쟁 모델을 구별하는 검사
4. 정량 오차·민감도·자원 검사
5. 비싼 실험·프로토타입·독립 검토

## 8. 검증 기록

검사마다 사전 통과 기준을 정한 뒤 다음 중 하나로 기록한다.

- `통과`: 기준을 만족함
- `실패`: 기준을 명확히 위반함
- `미검증`: 필요한 자료나 실행이 없음
- `판별력 부족`: 경쟁 모델도 같은 결과를 예측함
- `범위 밖`: 검사 조건이 모델 적용 영역을 벗어남
- `N/A`: 이 주장 유형과 결정에는 실질적으로 관련 없음

`N/A`는 누락을 숨기는 용도가 아니다. 이유를 한 문장으로 적는다.

## 9. 수정 루프

검증 실패를 다음 층으로 분류한다.

- 자료 실패
- 계산 실패
- 정의 실패
- 가정 실패
- 표현 실패
- 모델 실패
- 적용 범위 실패
- 구현·자원 실패

실패가 발견되면 해당 층을 수정한다. 수정 전후에 다음을 남긴다.

```text
실패한 검사:
공격받은 층:
수정 전 주장:
수정한 내용:
수정 후 주장:
확신 또는 적용 범위 변화:
```

한계 문단만 추가하고 핵심 결론이 그대로라면 수정 루프가 완료되지 않은 것이다.

## 10. 쉬운 설명과 정밀한 설명의 교차 검사

최종 설명을 두 층으로 만든다.

- **쉬운 설명**: 전문용어 없이 핵심 작동 과정을 설명한다.
- **정밀한 설명**: 변수, 조건, 근사, 자료, 예외와 검증 결과를 보존한다.

다음을 확인한다.

- 쉬운 설명에 원인과 결과 사이의 단계가 빠지지 않았는가?
- 비유가 실제 관계를 뒤집거나 없는 메커니즘을 만들지 않았는가?
- 정밀한 설명의 조건과 실패 범위가 쉬운 설명에도 흔적으로 남아 있는가?
- 쉬운 설명을 못 하는 지점이 실제 이해 공백인지 확인했는가?

## 11. 깊이별 최소 실행

| 수준 | 필수 실행 | 선택 실행 |
|---|---|---|
| L0 | 현상 재표현, 즉시 검사 1개, 변경 조건 | 경쟁 모델이 불필요하면 생략 가능 |
| L1 | 핵심 루프, 최소 모델, 경쟁 설명, 직접 점검 | 간단한 표 또는 모델 카드 |
| L2 | 표현 토너먼트, 근사 원장(해당 시), 판별 검사, 수정 기록, 자기비판 | 프로토타입·민감도 분석 |
| L3 | L2 전체, 독립 검증, 재현 기록, 최신 권위 자료, 전문가 검토 필요성 | 보수적 시나리오와 안전 여유 |

## 12. 종료 규칙

다음 중 하나일 때 현재 작업을 종료한다.

- 성공 기준을 충족하고 중요한 반대 증거를 처리했다.
- 추가 검증의 기대 가치가 비용보다 작다.
- 핵심 정보가 없어 조건부 결론 이상으로 나아갈 수 없다.
- 모델들이 현재 자료에서 구별되지 않아 다음 판별 검사가 명확해졌다.

종료는 완전한 지식의 선언이 아니다. 남은 공백을 보존한 채 현재 결정에 충분한 상태를 뜻한다.
